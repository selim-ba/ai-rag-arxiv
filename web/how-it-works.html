The two paths a question can take

Every answer on the demo is labelled pipeline or agent path. They are two different routes through the same system, and the difference is measurable, which is why the labels are shown rather than hidden.

The pipeline — what most answers use

The direct route: search, then answer. No decisions, no extra model calls. This is the configuration every published number on the front page describes.

Your questionas typed
↓
Search the 874 chunks each paper is split into chunks of a few hundred words, and every chunk is stored twice over: as an embedding that captures meaning, and as a word index. Both are searched at once and the two rankings are merged. Takes about 2 milliseconds.
↓
Answer from those chunks, or refuse the model is shown the five best-ranked chunks and nothing else, so anything it says has to come from them. It never writes the arXiv numbers itself; it points at a chunk, and the real number is filled in afterwards from the search results, which is why a citation on this page always leads to a paper that exists. If the chunks do not support an answer, it says so.

The agent path — used where deciding helps

Adds two things: a router that decides what kind of question this is before searching, and a grader that checks the retrieved chunks before answering.

Your question
↓
Route — what kind of question is this? about the papers in general · about specific named papers · or about the library itself
↓
A question about the library “which papers do you have?” is a question about the catalogue, not about the research. It is answered straight from the list of indexed papers, with no model involved at all — asked to produce a list of papers, a language model will happily write a convincing one that does not exist.
A question about the research search the chunks, narrowed to the papers you named if you named any. “V-JEPA” is matched to a paper filed as Revisiting Feature Prediction… through a hand-written table of the names people actually use.
↓
Grade — can these chunks answer it? a second, cheap model call reads the retrieved chunks next to the question and answers yes or no. To say yes it must also copy out the exact sentence that supports it; that quote is then checked against the chunk in code, and a quote that cannot be found there is thrown away. So the grader is taken at its word only when its word can be verified. When it says no, the question is left to the generator, which refuses rather than guessing.
↓
Answer, or refuse
Why it is not the default, with numbers. Narrowing the search to named papers finds two more answers on the 34-question test set — and makes the system answer two questions it should have refused, because a question scoped to a plausible paper hands the generator something that looks like evidence. Refusal accuracy falls from 0.925 to 0.875. For a system whose main claim is that it declines what it cannot support, that is not a good trade, so routing is used only where it is unambiguously the point.

Which path answers which question

  • Anything you type into the box takes the pipeline. It is the default, and the configuration every number on the front page was measured on.
  • “Which papers do you have?” takes the agent path, because recognising that kind of question is the router's whole job — and the answer then costs nothing.
  • A question naming one paper takes the agent path in the recorded examples, to show the name-matching at work.

The rule underneath: the pipeline is used whenever deciding first would be a risk, and the agent path whenever deciding first is the point.

What both paths share

  • Citations cannot be fabricated. The model never sees an arXiv number — it points at a chunk, and the number is filled in from the search results afterwards. This was not a precaution: an early version invented 2606.09985 for a paper numbered 2506.09985.
  • Follow-up questions are rewritten first. “and does it train a policy network?” becomes “Does PlaNet train a policy network?” before anything searches, so every component sees one self-contained question. The rewrite is shown to you, because a question answered differently from the one you typed is something you should be able to see.
  • Refusal is a real outcome, not an error. Six deliberately unanswerable questions sit in the test set for exactly this reason, and getting them right counts as much as answering the rest.
